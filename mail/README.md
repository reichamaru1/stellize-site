# Stellize メールレター

HTMLメールを作り、Googleスプレッドシートから配信するための一式です。

```
mail/
  builder/index.html    ← 書く場所（ブラウザで開く。左に原稿、右に完成形）
  templates/            ← 見た目の実体（base.html / base-daily.html / blocks.html / themes.json）
  render.js             ← 原稿記法 → HTML の変換。ここ1つでブラウザもGASも動く
  voice.js              ← 日刊の書き方チェックと曜日枠の定義
  samples/              ← 文例
  preview/              ← 生成された確認用HTML（手で編集しない）
  build.mjs             ← 上の素材から GAS 用ファイルとプレビューを作る
  daily.mjs             ← 日刊の受け渡し口（メモを読む／下書きを積む）
  test/daily-e2e.mjs    ← その通し確認（Googleには触らない）

gas/newsletter/         ← 配信ツール（Apps Script）。設置手順は同フォルダの SETUP.md
```

**テンプレートを直したら、必ず再生成してください。**

```bash
node mail/build.mjs
```

`gas/newsletter/Templates.gs` `Render.gs` `Voice.gs` `mail/builder/templates.js` `mail/preview/*` が作り直されます。
生成物を直接編集しても、次のビルドで消えます。直すのは `mail/` 側です。

---

## 1. 書く

`mail/builder/index.html` をブラウザで開きます（ダブルクリックで開けます）。

- 左に原稿を書くと、右に**実際に送られるHTMLそのもの**が出ます
- 「レターの型を入れる」から骨組みを流し込めます。空欄を埋めるだけで形になります
- 下に出る「確認したい点」は、送る前に自分で気づくためのものです
- 書けたら「スプレッドシート用にコピー」→ 原稿シートに貼り付け

書きかけはブラウザに残るので、閉じても消えません。

---

## 2. 日刊と営業レターは別物

2種類あり、**目的が違うので作りから分けています**。混ぜると両方効かなくなります。

| | 日刊 | 営業レター |
|---|---|---|
| 相手 | 自分で登録した読者（オプトイン） | 就労支援事業所（公開アドレス） |
| 頻度 | 平日毎日 | 月1〜2回 |
| 目的 | **信頼をつくる** | 相談につなげる |
| 骨格 | `base-daily.html`（580px・軽い） | `base.html`（600px・レター） |
| CTA | **置かない** | 1つだけ置く |
| 長さ | 600〜900字 | 制限なし |

### 日刊の枠（曜日固定）

「今日は何を書くんだっけ」が日刊を殺すので、曜日で固定しています。
ターゲットも枠ごとに割り当ててあるので、読者は自分の関心の日だけ読めば済みます。

| 曜日 | 枠 | 誰に効くか |
|---|---|---|
| 月・木 | **現場で見たこと** | 両方。訪問先で目にした場面をひとつ。解釈は最小限 |
| 火 | **手を動かしてみた話** | 生産活動を広げたい施設。撮り方・値付け・見せ方・作業の切り出し |
| 水 | **考えていること** | 両方。制度・お金・業界。解説ではなく意見として |
| 金 | **AIを試してみた話** | WelfareAIに関心のある施設。自分で試した結果を、失敗から |

枠の定義は `mail/voice.js` の `DAILY_FRAMES` にあります。原稿シートの「枠」列で選びます。

### 日刊の書き方（上から下ろさない）

情報を配ることが目的ではなく、信頼をつくることが目的です。この差は文体に出ます。

- **主語は「私」。** 「事業所は〜」と大きくした瞬間に評論になります
- **教えない。** 「〜しましょう」「ご存じですか」を使わない。「こうしたら、こうだった」で書く
- **失敗から書く。** うまくいかなかったところを書くと、いちばん信用されます
- **盛らない。** 「劇的」「圧倒的」は、福祉の現場では盛った瞬間に信用が落ちます
- **現場の人の言葉を、自分の言葉より上に置く**
- **売らない。** CTAは置かない。売り込みは月1の営業レターの役目です
- **オチをつけなくてよい。** 「まだ分かりません」で終わって成立します

これは意志だけだと必ず崩れるので、**機械で拾えるところは拾っています**（`mail/voice.js`）。
エディタで日刊を選ぶと、教える構え・誇張・大きすぎる主語・売り込みを指摘します。
配信パネルの送信前チェックにも同じものが入っています。

指摘は目安であって、審判ではありません。必要があってその言葉を選んだのなら、そのまま出してかまいません。

### 日刊の回し方

```
菊野さん（スマホ）        Claude（手元）              菊野さん（スプレッドシート）
  ネタ帳に1行  ────────▶  memos で受け取る
                          下書きを書く
                          draft で積む  ────────▶  直す → テスト送信 → 送信
```

```bash
node mail/daily.mjs status    # 今日の枠、未使用メモ、直近の号
node mail/daily.mjs memos     # 溜まっているメモ
node mail/daily.mjs draft 下書き.json
```

接続先は `.stellize-mail.json`（gitignore済み）。作り方は `gas/newsletter/SETUP.md` の「9. 毎日の下書きを自動で積む」。

**積まれた原稿は必ず「下書き」です。** このツールから送信されることはありません。
送るかどうかは、人が配信パネルで決めます。

読者はまだゼロです。**最初の3週間は原稿を積むだけにして、その間に登録導線を作る**ことを勧めます。
配信開始のときに15本のストックがある状態になり、日刊が続く確率が上がります。

## 3. 営業レターの型

読み手の頭は、だいたいこの順に動きます。型はこの順番に沿っています。

| 順 | やること | 使うブロック |
|---|---|---|
| 1 | **相手の現実を言い当てる** ── 「うちのことだ」と思ってもらう | 書き出しの段落 |
| 2 | **手を止めさせる** ── 見方をひっくり返す一行 | `:::statement` |
| 3 | **詰まりどころを並べる** ── 責めない。仕組みの話にする | `##` ＋ `-` |
| 4 | **手立てを見せる** ── 何が起きるかを、動作で書く | `##` ＋ `+` |
| 5 | **証拠を置く** ── 数字と、他人の言葉 | `:::numbers` `:::voice` |
| 6 | **条件を隠さず出す** ── 費用・回数・断り方まで | `:::offer` |
| 7 | **行動をひとつだけ頼む** ── 迷わせない | `:::cta` |
| 8 | **追伸** ── いちばん強い理由をもう一度 | `:::ps` |

書くときに効くこと。

- **導線は1通に1つ。** 選択肢を増やすと、選ばれるのではなく、選ばれなくなります
- **数字を最低1つ。** 「多くの事業所で」より「4事業所・38名」のほうが、話の輪郭が出ます
- **証言は整えすぎない。** 言われたままの言葉のほうが届きます
- **断り方を書く。** 「資料の送付だけでも構いません」の一行が、返信の壁を下げます
- **件名は25文字まで。** スマホの一覧ではそこで切れます
- **プリヘッダーを必ず書く。** 空だと本文の冒頭が拾われ、「{{宛名}}様」だけが並びます

## 4. 原稿の記法

| 書き方 | できるもの |
|---|---|
| ふつうの文 | 段落。**空行**で段落が分かれ、行内の改行はそのまま改行になります |
| `## 見出し` | 中見出し（明朝＋星＋罫） |
| `### 小見出し` | 小見出し（ゴシック＋金の縦線） |
| `- 項目` | 箇条書き |
| `+ 項目` | チェック付き。「得られること」を並べるとき |
| `\| 費用 \| 15,000円` | 条件の表 |
| `> 引用` / `>> 出典` | 引用と出典 |
| `**太字**` | 太字 |
| `==マーカー==` | 蛍光ペン風の強調 |
| `[文字](URL)` | 行の途中ならリンク。**行がまるごとこれ**ならボタン |
| `[[文字]](URL)` | 枠線ボタン（副次的な導線） |
| `![説明](URL)` | 画像。`![説明](URL "キャプション")` で説明文つき |
| `!![説明](URL)` | 冒頭の全幅画像。カードの一番上に敷かれます |
| `---` | 星の区切り線 |
| `:::statement` … `:::` | 手を止めさせる一行（明朝・大きめ・全幅） |
| `:::numbers` … `:::` | 数字を3つまで。1行を `値｜単位｜説明` |
| `:::voice 名前｜肩書｜写真URL` … `:::` | 現場の声。写真URLは省略できます |
| `:::offer 見出し` … `:::` | 条件をまとめた枠。中に `\| キー \| 値` を書けます |
| `:::cta ラベル｜URL` … `:::` | 行動をうながす帯。`※` で始まる行は小さな注記になります |
| `:::cards` … `:::` | 2列のカード。1行を `タイトル｜説明` |
| `:::ps` … `:::` | 追伸 |
| `::: ラベル` … `:::` | 補足の枠 |
| `-- 署名` | 署名。次の行に `![](顔写真URL)` を1枚だけ置けます |
| `{{宛名}}` | 差し込み。ほかに `{{法人名}}` `{{事業所名}}` `{{都道府県}}` |

差し込みは、`宛名` が空なら `事業所名` → `法人名` → 「ご担当者」の順に落ちます。誰に送っても不自然にならないようにしてあります。

## 5. 配色（テンプレート）

| キー | 使いどころ | 主色 |
|---|---|---|
| `daily` | 平日毎日の読み物 | 深緑（骨格も専用） |
| `b2b` | 就労支援事業所へのご案内 | ネイビー × ゴールド |
| `newsletter` | 定期便のメルマガ | ラベンダー |

| `partner` | パートナー・社内レポート | 深緑 |

配色は `mail/templates/themes.json` にあります。増やすときはここに1エントリ足して `node mail/build.mjs`。

## 6. メールHTMLの制約（触るときに知っておくこと）

メールクライアントはブラウザほどCSSを解しません。`templates/` を直すときは次を守ってください。

1. **レイアウトは `<table>` だけ。** flex / grid / position は効きません
2. **色・余白・文字はインライン `style`。** `<style>` はレスポンシブとダークモードの上書きだけ（Gmailアプリの一部は `<style>` を捨てます）
3. **Webフォントは読み込まない。** Gmailが対応しないので、端末のフォントに任せます（明朝＝ヒラギノ明朝/游明朝）
4. **グラデーションには必ず `bgcolor`（単色）を併記。** Outlookは `background-image` を無視するので、単色でも成立する配色にします
5. **画像は絶対URL。** `alt` を入れ、画像オフでも意味が通る文にします。画像には色と書体も指定します（`alt` が既定のリンク色で出るのを防ぐため）
6. **HTMLは92KBまで。** Gmailは約102KBで本文を切り、その先に配信停止リンクが隠れます。エディタが警告します

**開封率は取っていません。** GASのWebアプリは画像を返せず、1x1の計測画像を置くと本文に壊れた画像アイコンが出るためです。
代わりに、自社サイトへのリンクへ自動で `utm_source=newsletter` を付けています。反応はGA4の流入で見てください。

---

## 7. 送る前に必ずやること

1. エディタの「確認したい点」を消す
2. 「スマホ 375px」でも見る
3. 配信パネルから**テスト送信**して、自分のスマホの実機で開く
4. リンクを全部押す。配信停止リンクも押す

---

## 8. 法令（送る前に読む）

広告・宣伝を含むメールには **特定電子メール法** がかかります。守るのは次の4つです。

- **事前の同意（オプトイン）が原則。** ただし、**法人が自らサイト等で公開しているメールアドレス宛に、事業のご案内を送る場合は同意が不要**です（同法3条1項の例外）。就労支援事業所へのご案内はここに当たりますが、**「どこで公開されていたか」を記録に残す必要があります**。購読者シートの「許諾の根拠」列に必ず書いてください
- **送信者の名称と住所を表示する。** フッターに入っています。設定シートを空にしないでください
- **受信拒否の通知先を表示する。** 配信停止リンクが入っています
- **拒否された相手に再送しない。** 配信停止は全号に横断で効き、CSV取り込みでも復活しません

個人のアドレス（`{{宛名}}` が個人名の相手）には、この例外は使えません。本人がフォームから登録し、確認メールのリンクを押した相手だけに送ってください（ツールはその流れに対応しています）。

## 9. 文例について

`mail/samples/` と、エディタの「レターの型」に入っている数字・証言は**文例です**。
そのまま送らず、実際の数字と、実際にいただいた言葉に置き換えてください。
証言に顔写真を載せるときは、本人の同意を取ってください。
