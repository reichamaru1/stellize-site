# 全国 就労支援事業所データベース（shuro-db）

就労移行支援・就労継続支援A型/B型・就労定着支援の事業所を、全国横断で検索できるアプリです。
WAM NET の公的オープンデータを取り込み、正規化・名寄せしてローカルの SQLite に格納します。

**外部ライブラリへの依存はありません**（Node 22.5+ 同梱の `node:sqlite` と標準モジュールのみ）。
地図表示のみ、ブラウザ側で MapLibre GL JS を CDN から読み込みます。

---

## 使い方

```bash
cd shuro-db
npm run fetch     # WAM NET からオープンデータを取得（data/raw/）
npm run build     # 正規化してDBを構築（data/shuro.db）
npm start         # http://localhost:8787
npm test          # 正規化ロジックのユニットテスト
```

- `npm run fetch` は最新期のみ取得します。`npm run fetch -- --all` で全期（2021年11月〜）、
  `npm run fetch -- 202509` で期を指定できます。複数期を入れると差分（新規・消失）が出ます。
- 取得済みのファイルは再ダウンロードしません。
- `npm run build` は毎回DBを作り直すため冪等です。

## データについて（重要）

### 出典

[WAM NET 障害福祉サービス等情報公表システム オープンデータ](https://www.wam.go.jp/content/wamnet/pcpub/top/sfkopendata/)
（独立行政法人福祉医療機構）

### 更新は年2回しかない

元データは **3月末・9月末時点のスナップショットが年2回** 配布されるだけです。
リアルタイムな事業所情報は原理的に作れません。本アプリは
「公的スナップショットを、鮮度を明示した上で横断検索できるもの」です。
画面には常にデータ基準日を表示しています。

### 利用条件（公開前に必ず確認すること）

WAM 側はオープンデータの二次利用にあたり **利用状況の報告フォームへの記入** を求めています。
一般公開する前に現行の利用規約を確認し、報告手続きを済ませてください。
本リポジトリはこの手続きを代行しません。

## Phase 0：実データ調査の結果

設計は推測ではなく実データの確認にもとづいています。以下は確認済みの事実です。

### 配布形式

| 項目 | 実測値 |
|---|---|
| 形式 | ZIP（中に単一CSV）、**UTF-8 BOM付き** |
| 配布単位 | **サービス種別ごとの全国一括**（都道府県別ではない） |
| 列数 | 29列（全サービス種別で共通） |
| 利用可能な期 | 202111 / 202203 / 202209 / 202303 / 202309 / 202403 / 202409 / 202503 / 202509 / 202603 |
| 一覧ページの文字コード | CP932（ZIP内CSVとは異なる） |

ZIPのファイル番号（`sfkopendata_202603_045.zip` の `045`）は**サービス種別を表しますが、
ページ上のラベルとの対応が読み取りにくいため決め打ちしていません。**
最終判定は CSV 内の「サービス種別」列の値で行っています。

実測した対応：`045`=就労継続支援A型 / `046`=就労継続支援B型 / `060`=就労移行支援 / `062`=就労定着支援

### 件数（2026年3月末時点）

| サービス種別 | 件数 |
|---|---|
| 就労継続支援B型 | 20,783 |
| 就労継続支援A型 | 4,650 |
| 就労移行支援 | 3,396 |
| 就労定着支援 | 2,038 |
| **合計** | **30,867** |

### 取得できる項目・できない項目

**含まれる**（29列）：都道府県/市区町村コード、指定機関名、法人名・かな・法人番号・住所・電話・FAX・URL、
サービス種別、事業所名・かな・**事業所番号**、事業所住所・電話・FAX・URL、
**事業所緯度・経度**、利用可能時間帯（平日/土/日/祝）、定休日、特記事項、定員

**含まれない**：対象障害種別、指定年月日、開設年月日、休止・廃止フラグ、平均工賃・賃金、
加算の取得状況、送迎の有無

→ 緯度経度が最初から入っているため、**ジオコーディングの工程は不要**です。
→ 工賃実績は別の公表物（厚生労働省が年度ごとに公表）であり、本アプリの対象外です。

### 欠損率（対象4種別・全期）

| 項目 | 欠損率 |
|---|---|
| 事業所名・かな・番号・住所・電話・緯度経度 | ほぼ 0% |
| 法人番号 | 約 6% |
| FAX | 約 9% |
| 定員（サービス単位） | 約 20% |
| 事業所URL | 約 40% |

**欠損は推測で補完していません。** 画面上は「未公表」と表示します。
欠損率は画面下部の「データの欠損状況を見る」から確認できます。

## 設計上の判断

### 1. 事業所番号は一意ではない

「事業所番号」は事業所の主キーになりません。実データで確認したところ、
**同一の事業所番号で、名称も住所も異なる事業所が 1,288 件**ありました。

一方 `NO（システム内の固有の番号）+ サービス種別` は完全に一意（30,867件）です。

### 2. 施設の同一性キーに住所を含めない

住所には**建物名・階数・部屋番号**が含まれ、これらは頻繁に変わります
（例：`澄川８８ビル２階` → `澄川８８ビル３階`、`PP千歳ビル` → `アスクゲートビル`）。
住所をキーに含めると、同じ施設が期をまたぐたびに別レコードに分裂します。

候補キーを実データ（202509→202603）で比較した結果：

| キー | 誤って「消失」扱いになる数 | 別事業所を混ぜる過剰マージ |
|---|---|---|
| 事業所番号 + 名称 + 住所 | 959 | 0 |
| **事業所番号 + 名称** ← 採用 | **576** | **0** |
| 名称 + 市区町村 | 530 | 618 ← 不採用 |

過剰マージを起こさずに誤検出を最小化できる「事業所番号 + 正規化名称」を採用しました。
この判断は `test/normalize.test.mjs` にテストとして固定してあります。

### 3. 消えたレコードは削除しない

スナップショットに現れなくなった事業所は削除せず `presumed_closed` として残し、
最終確認期を記録します。UI では「最新データに掲載なし（〇年〇月が最後）」と表示します。

ただしこれは**廃止の確認ではありません**。事業所番号の変更・改称・移転でも同じ状態になります。
そのため、名称と市区町村が一致する現役レコードがある場合は
**名寄せ候補として詳細画面に提示し、自動では統合しません**（現在 718 件）。

### 4. 検索は FTS5 ではなく LIKE

FTS5 の trigram トークナイザは3文字未満のクエリに反応しないため、
「就労」「東京」といった2文字の日本語検索が機能しません。
正規化済みカラムへの `LIKE` は 3万件規模で **1.7〜20ms** で応答するため、こちらを採用しました。

検索文字列は全角/半角・大文字小文字・カタカナ/ひらがなを正規化して突き合わせます
（「スマイル」でも「すまいる」でも同じ 367 件がヒットします）。

### 5. SQLite を使う理由

元データが年2回更新の読み取り中心のデータであり、サーバ運用を必要としないためです。
PostgreSQL + PostGIS は運用コストに見合いません。

## 構成

```
src/
  ingest/
    sources.mjs     データソース定義（新しいソースはここに1つ追加する）
    fetch.mjs       一覧ページを解析してZIPを発見・取得（URLはハードコードしない）
    unzip.mjs       依存なしのZIP読み取り
    csv.mjs         RFC4180準拠のCSVパーサ
    normalize.mjs   正規化（全角/半角・かな・住所分解・法人格除去）
  db/
    schema.sql      スキーマ
    build.mjs       raw → normalized → merged、スナップショット差分、名寄せ候補
  server.mjs        読み取り専用API + 静的配信
public/             検索UI（ビルド不要）
test/               正規化・同一性キーのユニットテスト
data/
  raw/<期>/         取得した生ZIP（再取得できないため保存する。gitignore対象）
  shuro.db          構築済みSQLite（gitignore対象）
```

### API

| エンドポイント | 内容 |
|---|---|
| `GET /api/meta` | データ基準日、サービス種別、都道府県、品質指標 |
| `GET /api/facilities` | 検索（`q` `pref` `city` `service` `capacity_min` `capacity_max` `status` `sort` `page` `per`） |
| `GET /api/facilities/:key` | 詳細（提供サービス、関連事業所、名寄せ候補、履歴） |
| `GET /api/cities?pref=` | 市区町村一覧 |
| `GET /api/trend` | 期ごとの掲載件数と新規・消失 |
| `GET /api/export.csv` | 検索条件と同じパラメータでCSV出力（BOM付き） |

## アクセシビリティ

当事者本人が使う前提で作っています。実測で確認済みの項目：

- フォーム要素すべてにラベルあり、名前のないボタンなし
- 見出し階層の飛びなし、正の `tabindex` なし
- 明色・暗色の両テーマでコントラスト比 WCAG AA 達成（実測 6.4〜17.2:1）
- スキップリンク、検索結果件数の `aria-live` 通知、詳細ダイアログ展開時のフォーカス移動
- 状態は色だけでなくテキストでも表示（「最新データに掲載なし」）
- 文字サイズ変更に耐えるよう高さを固定していない
- 600px 未満では定義リストを縦積みに切り替え
