# 俺の事業を管理せよ

Stellizeの事業を1画面にまとめるデスクトップアプリ。
**外部ライブラリへの依存はありません**（Node 22.5+ 同梱の `node:sqlite` と標準モジュールのみ）。

```
お金
  ダッシュボード   その月の収支・契約・フォロー待ち・直近の動き
  お金の流れ       入出金の推移とカテゴリ別、明細検索
  月次損益         年ごとのP/L（売上・売上原価・販管費・利益）2023〜2026
  経費・勘定       勘定科目別・経費カテゴリ別、明細
  計画と実績       月次の目標／実績／目安、事業パラメータ
売る
  顧客・案件       商談パイプライン / 契約一覧 / 人脈台帳 / 名刺 / 協業先
  交流会           会ごとの費用対効果（アポ単価・成約単価）
  事業所リスト     全国の就労支援事業所 32,147件を検索
  メルマガ         今日の枠・ネタ帳・直近の号（配信ツールに接続）
発信
  SNS運用          アカウント設計・投稿カレンダー・投稿記録・数字と改善・参考事例
  料金表           単価・原価・粗利率
  取り込みの検算   シートの集計との突き合わせ、取込ログ、判定ルール
  設定             メルマガ連携、取り込み手順
```

## 起動

`俺の事業を管理せよ.app` をダブルクリック。専用ウィンドウが開きます。
（Chrome / Edge / Brave があればアプリモード、無ければ既定のブラウザ）

ターミナルから動かす場合：

```bash
npm start        # http://localhost:8710
```

## SNS運用

手動記録版です。TikTok/Instagramの他社データを自動で取る仕組みは入れていません（理由は下の「外部APIの制約」）。

| タブ | 中身 |
|---|---|
| 今の状況 | アカウント設計の要約、期限をすぎた予定、これから出す予定、直近の投稿 |
| 投稿カレンダー | 月の枡に予定と実績を並べる。灰＝案／金＝台本と予約／緑＝公開 |
| 投稿 | 案から公開後の数字まで1行で持つ。「台本」ボタンでClaudeに渡す材料が出る |
| 数字と改善 | 形式別・柱別・曜日別・月別の保存率と反応率。保存率の高い投稿と低い投稿 |
| 参考事例 | 伸びている他社投稿を、伸びた理由と取り込む要素つきで記録 |
| アカウント設計 | 誰に何を届けるか。台本と投稿可否の判断基準になる |

**アカウント設計を先に決めてください。** 台本の良し悪しは、ここが決まっていないと判断できません。

台本はこのアプリが書くのではなく、**アカウント設計と投稿のテーマを組み合わせた「Claudeに渡す文面」**を作ります。返ってきた台本を投稿の台本欄に貼る流れです。アプリにAIが入っているふりはしていません。

保存率は「保存 ÷ リーチ」で、リーチが0の投稿は率の計算から外しています（0で割ると平均が壊れるため）。

### 外部APIの制約

| | 自社の数字 | 他社の数字 |
|---|---|---|
| Instagram | 公式APIで取得可（保存・リーチ含む） | 公式APIで **いいね・コメント・投稿内容は取得可**。保存・リーチは不可 |
| TikTok | 公式APIで取得可 | **公式手段なし**（Research APIは商用利用不可） |

スクレイピングは両社の規約で禁止のため使いません。

## 検索・絞り込み・編集

明細を持つ画面には、共通の操作がつきます。

- **検索欄** … その表の主要な列をまとめて全文検索（Enterで実行）
- **絞り込み** … 列ごとのプルダウン。実際に入っている値だけが、件数つきで並ぶ
- **期間** … 日付・月を持つ表は開始〜終了で絞れる
- **並び替え** … 見出しをクリック
- **合計** … 絞り込んだ結果の金額合計が上に出る
- **編集** … 行の「編集」で右からフォーム。「＋ 追加」で新規行
- **削除** … 編集フォームの中から

対象は16表すべてです（入出金明細・経費明細・人脈台帳・名刺・契約一覧・商談パイプライン・
協業先・交流会・料金表・月次損益・月次の目標実績・週次KPI・月次収支サマリー・
事業パラメータ・カテゴリ判定ルール・PDF取込ログ）。

列の定義は `src/tables.mjs` の1か所にあります。表名・列名は必ずここと照合してからSQLに使うので、
画面から不正な名前を送っても通りません。

### 編集した行は取り込みで上書きされません

画面で直した行には編集の印（`edited_at`）が付き、`npm run import` はその行を飛ばします。
これが無いと、シートを取り込み直すたびに手で直した内容が黙って消えます。

取り込みの最後に、上書きしなかった行数が出ます。

```
※ 画面で編集済みのため上書きしませんでした： 入出金明細 1件
```

シートの値に戻したいときは、その行の編集フォームで **「シートの値に戻す」** を押してください。
印が外れ、次の取り込みでシートの値が入ります。

アプリで追加した行は元のシートに対応が無いので、取り込みの影響を受けません。

### 区分の考え方

売上と経費が同じ表に縦に並んでいるため、区分を取り違えると売上に経費が混ざります。
シート自身の並びが区分を表しているので、名前から推測せずそれに従っています。

| 区分 | どこで切れるか |
|---|---|
| 売上 | 〈売上〉から |
| 事業経費 | 「販売費及び一般管理費」から |
| **個人支出** | **「経費合計」から下**（家賃光熱費・生活費・借金返済・積立保険・貯蓄） |
| 指標 | 「支出合計」から下（利益・内部留保・残額）と、件数・率の行 |

目標側には「経費合計」の区切りがありません。そこで、実績側で経費合計より下に
**しか**出てこない項目名（家賃光熱費など）を覚えておき、目標側でその名前が出た行から
下を生活のお金として扱います。「借金返済」のように販管費にも個人にも出てくる名前は
区切りに使いません。使うと、目標側の経費が丸ごと個人に倒れます。

表の下には料金表が続き、月の列位置が同じです。罫線行で切らないと、
単価が「◯月の金額」として売上に入ります。

**項目名の無い行に注意。** シートでは、支出をぜんぶ足した行に項目名が入っていません
（上のセルと結合されているため）。結合セルの引き継ぎに任せると、直前の分類名
（「その他雑費」）が付いて、経費が倍に膨らみます。積み上げと一致するかどうかで
合計行かを確かめ、合計として別に持っています。

**大分類を飛ばした行。**「借金返済 ｜ ｜ 親族」のように中分類を飛ばす行があります。
この大分類は中分類の親ではないので、次に中分類だけの行（「｜ 積立保険 ｜ アクサ生命」）
が来たら引き継ぎを切ります。切らないと別の項目が前の分類にぶら下がります。

### お金の区分表（実取引のほう）

「お金の流れ管理」は、取引を **business / personal** に分けています。ただしこれは
**どの口座から出たか**でしかありません。そのまま使うと、

- 事業口座で払った生活費が「事業の経費」になる
- 口座間の移し替えが「事業の収入」と「事業の支出」の両方に立つ
- 借入・ファクタリングの入金が「売上」になる

ということが起きます。実際、修正前のダッシュボードは2026年の事業の収入を
¥2,823,401 と出していましたが、そのうち ¥938,572 は移し替えと借入でした。

そこで、カテゴリごとに「それは何のお金か」を決める表を持っています。

| 区分 | 中身 | 損益に入れるか |
|---|---|---|
| 売上 | 研修講師料・その他収入 | 入れる |
| 経費 | 会費・ツール・交際費・手数料 | 入れる |
| 個人 | 生活費・食費・家賃・交通費 | **入れない** |
| 振替 | 口座間振替・現金引き出し・自分あて送金・貯蓄 | **入れない**（収入でも支出でもない） |
| 資金調達 | 借入・ファクタリングとその返済 | **入れない**（資金繰りの話） |

- 画面の「手残り」の下から直せます。直すと上の数字がすぐ変わります。
- 1件だけ例外にしたいときは、取引明細の「区分」を埋めます。そちらが優先されます。
- 新しいカテゴリが増えたら自動で足され、**要確認**が立ちます。

## 検算

```bash
npm run verify
```

件数が合っていても、列を1つ読み落とせば金額は狂います。そこで3段で確かめています。

1. **連番に欠けが無いか** … 行が落ちていないか
2. **差引残高が最後まで積み上がるか** … 1円でも読み違えたら合わない
3. **シート自身の集計との突き合わせ** … 合わない場合はどちらが正しいかを示す

さらに、件数でも残高でも見つからない「分類の取りこぼし・二重計上」を、
**足し戻し**で確かめています。区分に分けたあと足し直して、シート自身の合計に
戻れば、落としも二重も無いと言えます。

現在の結果：

- 入出金明細 247件すべてで差引残高が一致（最終 -¥1,159,341）
- 月次損益：総売上 24/24か月、販管費 24/24か月が内訳と一致
- 収支ダッシュボード：**支出が12/12か月、経費明細と完全一致**
- 収支計画の目標：事業経費＋個人支出 ¥5,521,436 ＝ **シートの支出合計と1円まで一致**
- 月次損益の経費：12/12か月で 内訳＝シートの経費合計
- 分類が空の行 0件 ／ 未来の日付の初回面談 0件
- お金の区分：33カテゴリすべて登録済み、人が見ていない区分 0件

一致しない箇所は、いずれも**シート側の内部矛盾**です（アプリの「取り込みの検算」画面の
いちばん上に、取り込みの誤りと分けて出しています）。

| 箇所 | 内容 |
|---|---|
| 月次収支サマリーの収入 | 2026-04〜12 が ¥412,030 から**1円ずつ増えている**。セルを下に引っぱった跡で、計画でも実績でもない |
| 収支計画の目標 総売上 | ¥14,772,103。内訳を足すと ¥10,619,488（差 ¥4,152,615）。内訳に無いものが総売上に入っている |
| 収支計画の実績 総売上 | ¥3,542,047。内訳を足すと ¥2,130,482（差 ¥1,411,565） |
| 【収入カテゴリ別】【支出カテゴリ別】 | 明細と噛み合わない。別シートを集計しているか、古い値 |
| 2024-01 の実績合計売上高 | 【トイエバ】¥149,000 がその月だけ合計から外れている |

**アプリ側では直していません。** 直すとシートと数字が食い違い、どちらが正かが
分からなくなるためです。画面には内訳から足した値を出し、シートの合計との差を
注記しています。

## まだ足りていないところ

- **シートの売上と口座の入金が月ごとに合いません**（検算画面に並べています）。
  請求と入金の月が違うのか、シートに書いていない入金があるのか、こちらの区分が
  違うのか。区分が原因なら「お金の区分表」で直せます。
- **SNS運用**は入れ物だけで、投稿・参考事例がまだ空です。
- **やること**が空のままです。商談の「いま追う案件」とつながっていません。
- メルマガ連携は設定待ちです。

## データの置き場所

| | 場所 | 誰が正か |
|---|---|---|
| お金・顧客・案件・KPI | `data/ore.db` | **このアプリ** |
| 事業所 32,147件 | `../shuro-db/data/shuro.db` | shuro-db（読み取り専用で開く） |
| メルマガ | GASのWebアプリ | スプレッドシート側 |

`data/` は `.gitignore` 済みです。**入出金・経費・人脈が入るのでコミットしないでください。**

## メルマガ連携

「設定」画面に、スプレッドシートの「📧 メルマガ」→「ネタ帳のURLと連携キーを表示」で出る
WebアプリURLと連携キーを入れます。連携キーは `data/ore.db` にだけ保存され、画面には出しません。

接続すると、メルマガ画面で今日の枠・未使用のメモ・直近の号が見え、
PCからもネタ帳にメモを残せます。**送信はこのアプリからは行いません**（配信パネルで人が押します）。

## 設計メモ

- 金額は円の整数で持つ。小数は使わない（消費税の丸めで必ず事故る）
- 日付は `YYYY-MM-DD` の文字列（SQLiteに日付型は無い）
- 表の見つけ方は「見出し行の列名」。行番号で決め打ちすると、シートに1行挿入されただけで全部ずれる
- ダッシュボードは暦の今月ではなく「記帳がある最後の月」を出す。月初に¥0が並ぶのを避けるため
